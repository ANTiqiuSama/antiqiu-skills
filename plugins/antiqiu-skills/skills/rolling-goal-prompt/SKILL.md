# 滚动目标记录

维护一份下一位执行者能继续工作的当前目标：用户要什么、哪些授权和限制有效、已知事实、下一步及完成条件。复用现有目标与固定入口；历史摘要、Wiki 和台账不能替代最新用户意图。

## 唯一入口

先找已有记录并核对是否适用。无记录且任务需要持久目标时使用 `GOAL_PROMPT.md`；已有版本消费者时沿用其正文、manifest 与固定指针，不另建竞争性目标。文件名、修改时间或最大版本号不能单独证明有效性。

写明修订号、更新时间和协调写入者。实质变化才递增修订：先写完整正文与消费者要求的校验元数据，再切换指针和实际入口。Windows/WSL 路径应指向同一文件。普通进度或监控唤醒不产生新版本。

## 内容与更新

记录交付物、范围、已有授权、必要依赖、输入输出位置、有效结果、未解决问题、具体下一步和可观察的完成条件。事实链接原始证据；区分假设、推断与建议。目标决定做什么，台账记录发生过什么，证据支持事实。

新材料改变决策时，先修正受影响的旧指令，再执行依赖步骤；不要只追加补充而留下相反命令。保留历史和负结果，只重开实际受影响的完成项。未验证事项不能写成完成，更新目标也不自动修改旧协议或扩大权限。

正文按目标消费者的实际字段与用户范围组织；需要润色专业文本时，必须先读取并使用 [academic-humanizer](../academic-humanizer/SKILL.md)，不另设文风规则。可用 [模板](assets/GOAL_PROMPT.template.md)，不强制章节数。有效证据可复用；目标维护、交接和检查点不新增审批，也不启动或恢复 `/goal`。严禁为普通正文编辑或备份例行计算哈希；仅在实际消费者需要版本绑定或明确完整性问题时检查最小相关范围。

## 交接与验收

交接给出固定入口/正文绝对路径、修订、具体工作、允许写入范围和完成条件，再补必要任务 ID、产物、验证及阻塞。无法跨机器读取时提供带修订与来源的必要快照，注明它是派发副本。缺少必需内容时先取回，继续不依赖它的工作。

默认由协调者合并更新。并行执行者回传其依据的修订、实际成果和建议；基线变动后先协调，不能覆盖别人的新修订。已有授权内的单一接手者可继续维护同一记录。

结束前用当前目标核对交付物、证据与剩余条件；只在版本不确定或正文变化时重读。区分阶段完成、进程成功和总体完成。必要条件未满足就继续授权内的工作，或报告具体阻塞及恢复条件；录用等外部决定不能写成已实现结果。

监控只读相关条目，普通进度留在现有状态中；不重复监控、不因等待改模型或擅自暂停目标。最终只交代当前入口、修订、成果与影响使用的缺口。
