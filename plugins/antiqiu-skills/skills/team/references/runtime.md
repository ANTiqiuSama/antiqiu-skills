# Codex Desktop 运行边界

版本能力以当前受支持的工具为准。不因等待而另建临时 Codex 任务或 standalone cron。用户明确授权后，可为项目创建或复用一个固定 Luna 执行任务，并把 heartbeat 附着于该任务。

## 模型和任务

附着 heartbeat 沿用其固定 Luna 任务的 `gpt-6-luna` / `low`。创建固定任务和 heartbeat 前必须有用户授权，并确认同一项目没有现存任务。不得以 prompt 假装切换实际模型参数；运行模型与 effort 必须从真实配置核验。项目绑定中的 `coordinator_id` 标识发起混动并负责科学协调的任务。固定 Luna 执行任务读取本技能后仍沿用该绑定，不自行成为科学协调者；未知的 `current_model` 保持 `null`，不得用执行者模型代填。

## 唤醒与调度

只使用用户已授权且真实存在的固定 Luna 任务/附着 heartbeat。入口包含唯一 SSoT、只读探针、稳定事件 ID 依据、停止条件和执行包路径；仅在事件变化时派发，禁止重复创建。持久状态和日志写在稳定文件，不能依赖跨任务 terminal session ID。

正常推进与无行动价值的变化保持安静；有意义变化、明确完成、失败或需要用户动作才通知。停止状态后不继续轮询；用户停止或科学失败不自动恢复。不得擅自暂停 Goal。

`/goal` active 与 heartbeat 是不同唤醒来源。当前 `update_goal` 可在用户明确要求时暂停本任务；它不接受其他任务 ID。处理其他任务时只使用实际支持的暂停入口，缺失时说明需要用户操作。不借目标数据库、底层接口或假完成代替暂停。用户已经暂停时保留状态，除非确有新证据表明恢复续轮。不要创建 goal 来等实验。

暂停必须核对实时状态。已有受支持的只读接口时可读取目标状态，例如 `thread/goal/get`，并用 `wait_threads` 的新鲜快照核对最新轮次 ID 和空闲状态。对已经观察到的快速续轮，选择能覆盖原有续轮间隔的短观察窗口，再确认最新轮次未变；单次检查少于 60 秒。工具若立即返回空闲，不把它当成已持续等待满请求时长。无需持续驻留或长期轮询；核验完成后交回唯一 heartbeat。

`automation_update` 返回 `Rendered automation card in the app.` 只证明卡片已展示。实际修改须收到更新成功结果，并回读同一计划的字段；不要将 `view`、`suggested_update` 或未应用的卡片说成已改期。若配置后来变化，记录当前事实并修正，不把先前成功当作永久保证。

## 等待与交接

当前轮次的 `wait_threads`、`wait_agent` 和进程会话 wait 可以等完成事件，不代表跨轮次或退出 App 后仍有持久订阅。按工具上限和会话响应约束等待，复用已有 session/agent id，外层等待覆盖内层；等待时推进独立工作，不重启进程。

派发事件后保存 `dispatched` 和时间；工具接受不等于目标轮次完成或 `handled`。同一稳定事件只派发一次。监看任务持有状态机、状态文件与运行日志；若身份/状态不明、需用户决策、停止或科学失败，停止自动动作并由协调者处理。恢复需满足 [长作业监看](wait.md) 的身份、checkpoint、进程和一次性条件。
