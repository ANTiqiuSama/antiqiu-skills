# 长作业监看

当前轮次能等完的短作业直接等完。需要跨轮次监看时，先确认真实作业仍存在，并核对 job ID、执行身份和项目绑定。没有真实且身份核实的作业时不建立监控。

每个项目只有一个固定 Luna 任务，heartbeat 附着该任务。创建任务和 heartbeat 前必须有用户授权；等待不另建临时 cron 或额外任务。Luna 使用 `gpt-6-luna`、`low` 执行，并持有 Grok CLI 会话及其稳定状态/日志/结果。heartbeat 稀疏检查已有进程和结果，不因长时间没有流输出或无新进度而重启、重派或重复调用模型。只读取该项目已有的只读探针和 checkpoint，不依赖另一任务的终端会话 ID，也不据此重新运行训练。

Grok 调用默认不设总时限且不设 idle timeout。只有用户给出的任务预算、明确认证错误/硬限流、进程退出或停止请求，才可停止该次运行；有限 timeout 必须有执行包预算依据，不能自动添加 120 秒上限。已完成结果的进程清理与推理失败分开记录，清理退出码不能覆盖已完成回执。

沿用 `monitor_policy.py` 的 15/60/240 分钟最小、初始、最大间隔与既有 `completion_history.py`。记录稳定事件 ID；无变化复用已有状态，不重复派发。已派发只表示交接尝试发生；只有接收方的实际结果证据才可标成处理完成。

停止请求、科学失败、未知状态、身份不符、checkpoint 无效或旧进程仍在运行时均不自动恢复。恢复仅当原 attempt、协议、代码、输入、配置/权重和执行身份全部匹配，checkpoint 有效，旧进程经证据确认已退出，且同一事故此前未恢复时，最多自动恢复一次；否则交由协调者决策。

不自动暂停 Goal。项目执行包定义监看身份与证据路径；状态字段及去重见 [state.md](state.md)，宿主工具边界见 [runtime.md](runtime.md)。
