# Refinement modes and output patterns

Use only the sections relevant to the current request.

## Modes

### Polish

Use when the source is already structurally sound.

1. Preserve paragraph order and argument shape.
2. Correct grammar, ambiguity, repetition, and inconsistent terminology.
3. Match the requested tone without making the writing sound generic.
4. Avoid adding headings or new claims unless needed for comprehension.

### Distill

Use when the reader needs the signal faster.

1. Identify the smallest complete statement of the purpose or thesis.
2. Rank details as essential, supporting, contextual, or removable.
3. Retain key evidence, numbers, constraints, caveats, and actions.
4. Remove duplicated rationale, throat-clearing, and examples that add no new meaning.
5. Prefer a compact hierarchy over a dense paragraph.

### Restructure

Use when useful content exists but the current order obscures it.

1. Group material by reader question rather than source order.
2. Choose a progression such as conclusion → evidence → implications → action.
3. Separate background, decisions, risks, and next steps.
4. Add headings only when they help navigation.
5. Reconnect moved content with explicit transitions.

### Challenge

Use for proposals, plans, arguments, strategy, and recommendations.

1. State the actual decision or claim.
2. Separate evidence, assumptions, and preferences.
3. Test missing alternatives, dependencies, failure modes, and reversibility.
4. Identify what would falsify or weaken the recommendation.
5. Strengthen the text with qualified conclusions, mitigations, and validation steps.
6. Do not turn an uncertain proposal into a confident commitment.

### Adapt

Use when the same meaning must work for a new reader or channel.

1. Preserve the underlying message and requested action.
2. Adjust context, terminology, depth, tone, and length to the audience.
3. Replace assumed knowledge with short explanations where necessary.
4. Match the channel: concise for chat, explicit for email, structured for a memo, scannable for a report.
5. Avoid stereotypes about audiences; rely on stated needs and context.

### Synthesize

Use when combining notes, documents, transcripts, or viewpoints.

1. Normalize terminology without erasing meaningful distinctions.
2. Organize by themes, questions, decisions, or chronology.
3. Mark agreement, disagreement, and missing evidence.
4. Preserve provenance for claims whose source matters.
5. Avoid false consensus and duplicate counting.
6. End with the combined conclusion, decisions, actions, and open questions.

## Document patterns

### Proposal or decision memo

Use: decision required → recommendation → rationale/evidence → alternatives → risks → validation or rollout → open questions.

### Plan or requirements text

Use: objective → non-goals → scope → constraints → approach → dependencies → milestones → acceptance criteria → risks → owners or next actions.

### Research or analytical summary

Use: question → answer/TL;DR → evidence → method or source limits → findings → implications → gaps → recommended follow-up.

### Meeting notes or transcript

Use: context → decisions → rationale → action items with owners/dates when present → unresolved questions → supporting notes. Never invent owners or deadlines.

### Technical explanation

Use: purpose → mental model → components → flow → invariants/interfaces → example → failure modes → operational or implementation notes.

### Status or incident report

Use: current state → impact → timeline → evidence → cause or hypotheses → mitigation → remaining risk → next update/action.

### Email or message

Use: purpose/request in the opening → only necessary context → decision or action needed → deadline/owner if sourced → courteous close.

### Article or narrative

Use: controlling idea → coherent arc → section-level purpose → evidence/examples → conclusion. Preserve intentional voice, rhythm, and ambiguity.

## Compression levels

- **Light** — retain nearly all content; improve clarity and wording.
- **Balanced** — remove redundancy and weak detail; retain full reasoning.
- **Executive** — retain conclusion, strongest evidence, major risks, and required action.
- **One-screen** — retain only what a reader must know or do now; disclose omitted nuance when it could change interpretation.

When the user gives a word, character, or format limit, treat it as a hard constraint unless doing so would create a misleading result. If the limit conflicts with fidelity, state the conflict briefly and provide the safest compliant version.
